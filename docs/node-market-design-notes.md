# 节点二级市场：讨论结论与对接说明

> 状态：**构想阶段，未动工**（2026-09-26）。项目负责人明确表示「慢慢构思，想好了再动工」。
> 接手的 Agent：**未经负责人明确要求，不要开始实现**。本文用于继续讨论或在获准后作为设计输入。
> 面向人的可视化纪要：https://claude.ai/artifact/1qsR71wo3GimDUdmbcQSPT （内容截至 §1–§5，不含 §6–§7）

## 1. 构想概述

用户（卖家）把自己的 VPS（多为低配「小鸡」）作为节点接入 AeraNexa（下称 AN），为自己节点的流量标价（元/G）。其他用户（买家）使用卖家节点时，按实际用量**扣买家的付费套餐流量**（不扣余额）。平台按卖家标价给卖家记**站内余额**，差价归平台。

定位：**极客资源共享**，差价不求盈利，目标是拉动站内人流。

## 2. 已拍板的决定

| # | 决定 | 备注 |
| --- | --- | --- |
| D1 | **不开任何提现通道**（含加密货币），卖家收入只进站内余额 | 防盗刷套现的核心；配套：卖家收入余额不可转让、不可兑换充值卡 |
| D2 | 以极客资源共享为主题，差价不求盈利 | 差价仍保留，作为防自刷缓冲及未来中转带宽成本 |
| D3 | 只能用**付费购买的**套餐流量消费卖家节点 | 试用、注册赠送、邀请奖励流量不可用 → 流量需按来源打标记 |
| D4 | 本站不支持退款 | 拒付仍可能发生，但因 D1 损失仅限该笔套餐 |
| D5 | 前期**邀请制**，由负责人挑选卖家 | |
| D6 | 卖家节点程序基于负责人自研的 **3x-node 精简副节点** | 源码在 `source/3x-node`（独立 git 仓库，`source/` 已被 gitignore） |
| D7 | 卖家节点**直连 AN**，不接 3x-ui 主控；自营节点继续走 3x-ui 主控 | 理由见 §6 |

## 4. 威胁模型与对策

**核心前提：卖家对节点有 root，节点上报的任何数据都不可信。** 加密、签名、mTLS、「每次变动请求面板」只能防第三方和防透支，不能防卖家本人（密钥和计数代码都在卖家机器上）。负责人曾提议「双层加密防 root 篡改」，结论是不可行，除非用 SEV-SNP/TDX 等硬件可信执行（门槛过高，暂不考虑）。

| 作弊手法 | 状态 | 对策 |
| --- | --- | --- |
| 盗刷支付后套现 | 已堵 | D1 |
| 卖家自买套餐刷自己节点 | 已堵 | 标价 < 买入价，刷一次亏一次 |
| 用赠送/试用流量刷 | 已堵 | D3 |
| 低价流量循环放大 | 已堵（若采纳 S1） | S1 |
| 余额转让/换卡变现 | 已堵 | D1 配套 |
| **虚报真实买家用量** | **需持续防** | 测试账号抽查（阶段一）→ 中转计量（阶段二）；单买家单节点用量上限；风险 Agent |
| 买家流量耗尽后透支 | 需实现 | 预授权额度：每次冻结一小块（如 1G），用完再申请，不足即断开 |
| **卖家窃取买家凭据** | 需实现 | 见 §6「凭据隔离」 |

计量方案按阶段：测试账号抽查（阶段一）→ 平台中转计量（阶段二，计数点在平台）→ 自研客户端做买卖双方交叉对账（阶段三，可选）。

其他风险（非技术）：买家使用卖家出口 IP 的连带责任；卖家可见买家连接元数据（需告知买家）；合规需上线前咨询专业意见。

## 5. 风控分层（风险评估 Agent）

| 层 | 执行者 | 职责 |
| --- | --- | --- |
| 实时层 | 规则与统计 | 阈值、异常分、抽查比对；确定性、低成本，负责标记 |
| 调查层 | AI Agent | 对被标记卖家拉取历史上报、抽查记录、账号关联，产出带证据的报告，推送到现有 Telegram bot（`src/bot`） |
| 决定层 | 管理员 | 在 bot 中确认处罚/忽略；扣保证金必须人工确认 |

约束：Agent 必须依赖可信数据（抽查/中转），不能只分析卖家上报；卖家可填写字段（节点名、描述等）只能当数据，须防提示注入。

## 6. 3x-node 与 AN 的对接结论

### 6.1 3x-node 是什么

负责人基于 MHSanaei/3x-ui 的 fork（仓库 `opxqo/3x-node`，GPL-3.0）。含两部分：完整主面板（版本 3.7.0）与**精简副节点 `3x-ui-node`**（Go，0.1.24-node，Xray 26.7.28）。精简节点：面向 128MiB Alpine/OpenRC，一行安装；仅 VLESS + TCP/RAW，安全层 none 或 REALITY（可选 Vision）；无网页；HTTPS 管理口默认 2053，自签证书 + 随机 Bearer Token；配置由上游**主动下发**（0.1.14 起移除了节点主动拉取）；本地 5 秒采样流量。文档：`source/3x-node/docs/node/README.md`，路由：`source/3x-node/internal/node/http.go`。

### 6.2 接口兼容性（仅静态比对路径，未实测）

- AN 的 `PanelClient` 白名单（`src/lib/server/panel/client.ts` `ALLOWED_ENDPOINTS`）用到的 6 个接口——`GET server/status`、`GET inbounds/list`、`POST clients/add`、`POST clients/update/{email}`、`POST clients/{email}/detach`、`POST clients/del/{email}`——精简节点**全部实现**，前缀同为 `/panel/api/`，信封同为 `{success,msg,obj}`，认证同为 Bearer。
- 上游 3x-ui 3.8.5 主控（`source/3x-ui/internal/web/runtime/remote.go`）调用子节点的全部接口，精简节点也都有。但精简节点的兼容基准是 fork 3.7.0（`ed6bc1d8`），与 3.8.5 的载荷细节需实测。

### 6.3 为什么卖家节点直连 AN（D7）

1. **结算必需**：3x-ui 主控的 `client_traffics.email` 全局唯一，只给用户合计，无法区分节点（见 `docs/node-domain-design.md` §2、§6），无法按卖家结算。直连后逐节点采集即可。
2. **信任隔离**：不可信机器不进入自营主控，避免主控被牵连。
3. 卖家身份、标价、保证金、结算都在 AN，经主控只多一份状态；卖家可在 AN 自助接入（填 Token + TLS 指纹）。

### 6.4 直连需补的工作（未实现）

- `PanelClient` 当前只有一套全局配置（地址 + Token）→ 需支持每节点一套（地址、Token、TLS SHA256 指纹）。
- Node fetch 需支持按证书指纹固定校验自签证书。
- 流量采集改为逐节点，得到「买家 × 卖家节点」维度。
- 入站分配仅限 VLESS（当前 `SYNC_PROTOCOLS` 为 vless/vmess/trojan）。
- **凭据隔离**：现设计「一个用户一个 UUID（`users.uuid`），全站通用」。卖家有 root 可读到下发的 UUID，拿去用自营节点或外泄。卖家节点必须使用**每个「买家 × 卖家节点」独立的凭据**，可单独作废。
- **暴露面板 IP**：直连时卖家能看到 AN worker 的来源 IP。可选对策：管理请求走独立出口/中转，或改为节点主动回连面板（也解决卖家 NAT 问题，但需重新评估 0.1.14 移除拉取的决定）。
- 现有 `/api/node/traffic` 使用全局共享密钥 `NODE_TRAFFIC_SECRET`，任意节点可冒充他人，不可用于卖家节点（精简节点每台有独立 Token，不受此影响）。

### 6.5 架构总览

| | 自营节点 | 卖家节点（二级市场） |
| --- | --- | --- |
| 接入 | 3x-ui 主控（现状不变） | AN 直连 3x-node 精简节点 |
| 协议 | 多协议 | 仅 VLESS |
| 用户凭据 | `users.uuid` 全站通用 | 每买家 × 每节点独立 |
| 流量统计 | 主控给的用户合计 | 逐节点采集 |

## 7. 建议路线与待确认问题

**阶段一 · 邀请制**：负责人邀请卖家；直连 + 每节点独立配置与证书固定；独立买家凭据；流量来源标记；标价上限自动计算；预授权扣费；测试账号抽查。
**阶段二 · 开放准入**：保证金准入；中转计量；实时异常检测；风险 Agent 接 Telegram bot；买家申诉。
**阶段三 · 规模化**：卖家信誉；评估自研客户端交叉对账。
**可立即做的零代码验证**：在本地 3x-ui 3.8.5 主控下挂一台精简节点，实测下发、流量、订阅，顺带验证 3.7.0 基准与 3.8.5 的兼容性。

待确认：
1. 是否采纳 S1（标价上限自动计算）、S2（保证金准入）。
2. 第一批邀请哪些卖家、多少人。
3. 预授权每次冻结多少流量。
4. 阶段二中转带宽成本由谁承担。
5. 卖家节点管理连接方向：面板主动连节点，还是节点回连面板。
6. 合规评估由谁、何时做。
