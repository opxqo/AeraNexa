# 3x-node × AeraNexa 封闭对接联调记录

日期：2026-09-26。代码分支：`3x-node-an-panel`，从 AN `main` 的 `a7c8776` 建立独立工作树。3x-node 使用独立仓库当前 `7f29a657` 源码构建的 Linux/arm64 测试程序，未修改该仓库。

## 实现范围

- AN 管理后台新增 `/admin/node-connections`。测试节点的地址、TLS SHA-256 指纹、加密 Token 和启停状态独立保存；Token 不回显。
- 现有面板客户端支持明确指定的 3x-node 目标。自营 3x-ui 仍使用原全局配置。节点请求限于六个原有白名单接口，自签证书必须匹配固定指纹；不允许重定向或降级校验。
- 测试连接只用于管理员手动联调，不进入 `nodes`、用户订阅、worker 同步、套餐扣量或卖家账本。

本地 Docker 运行 3x-node 和 Xray 26.7.28；管理口映射到 `127.0.0.1:32053`，VLESS 测试入站映射到 `127.0.0.1:32443`。另用独立 MySQL 8.4 容器与 `aeranexa_node_lab` 数据库验证后台；未连接主工作目录的数据库。TLS 指纹由测试证书计算，Token 仅从隔离配置读取，未写入仓库。

## 流量计数实测

使用独立 Xray 客户端经测试 VLESS 入站访问本地 HTTP 源站：GET 响应体 65,536 字节，POST 请求体 32,768 字节。节点在一次采样周期后上报 `up=33,026`、`down=65,765` 字节；读数大于纯请求/响应体，是包含 HTTP 报文开销的合理结果。连续两次 `inbounds/list` 读取相同计数，未因查询而重复增长。

重启节点后读数仍为 `33,026 / 65,765`。随后在**隔离节点**调用重置接口并再次 GET 65,536 字节，读数从新世代累计到 `up=92`、`down=65,650`。这说明节点侧累计计数可读取、持久化并可重置；AN 尚未把这些读数用于买家扣量或卖家结算，也未验证受恶意卖家控制时的可信性。

## 真机联调：Alpine 容器 VPS（2026-09-26 追加）

环境：美国芝加哥 Alpine（Podman）小鸡，1 GB 硬盘、200 GB/月流量，amd64，节点 `0.1.24-node`。AN 在本地 `localhost:3000`，通过服务商映射的管理端口访问。客户端用本机 Docker 里的 Xray 26.7.28，经 SOCKS 走 VLESS/TCP（无加密）入站。数据库为测试库。

### 已验证

| 项 | 结果 |
| --- | --- |
| 六个接口（含 TLS 指纹固定、Bearer 认证）经公网 NAT 映射 | 通过；随机 `an-test-*` 客户端已创建、更新、摘除、重新挂载、删除 |
| 单用户流量 | 下载 10,485,760 / 上传 5,242,880 字节；节点读数下行 10,504,317、上行 5,251,174，开销 0.18% / 0.16% |
| 多用户分账 | 两个客户端各发不同大小流量（3 MiB、7 MiB + 1 MiB），读数只对应各自流量；未使用的客户端读数逐字节不变；开销 0.24%–0.32% |
| 重复读取 | 未使用客户端的读数多次读取保持不变，读取本身不增长 |
| 节点重启后保留 | 重启前后读数逐字节相同（重启由操作者在 VPS 上手动执行） |
| 客户端中途断线 | 请求 1 GiB、传输约 3 秒后强杀客户端；节点记账 3,343,947 字节，未在断开后继续计数 |
| 两个入站隔离与公网端口映射 | 公网 36778→入站 #1，公网 38443→容器内 8443（入站 #2）。各发 2 MiB / 4 MiB，两个入站只记各自流量，其余客户端读数不变；两入站互换客户端 UUID 均被拒绝（TLS 握手前断开） |

### 需要记入计费口径的发现

1. 节点记的是**发出的字节数**，不是终端应用读走的字节数。上述断线测试中，应用侧收到 1,267,807 字节，节点记 3,343,947 字节；差额是发出后滞留在隧道和缓冲区中的数据，含本测试环境（Xray 客户端加 Docker 端口转发）的缓冲，真实客户端的差额应更小，尚未另行测量。
2. 入站级与客户端级两套计数**口径不同**：每个连接入站级上行比客户端级多约 43 字节（与 VLESS 请求头长度吻合，为推断，未核对源码），客户端级下行比入站级多 2,838 字节（原因未查明）。被中断的连接下行多出约 14 KB。扣买家流量应固定使用其中一套，不能混用。
3. 断线与正常结束的连接在计数上没有观测到丢失，但样本很少，不代表所有异常路径。
4. 被拒绝的连接（如用错入站的 UUID）会给**入站级上行**各增加约 373 字节，且不归属任何客户端；下行不受影响。因此入站级读数会被无凭据的连接推高，扣买家流量必须使用客户端级计数。
