# 3x-node × AeraNexa 封闭对接联调记录

日期：2026-09-26。代码分支：`3x-node-an-panel`，从 AN `main` 的 `a7c8776` 建立独立工作树。3x-node 使用独立仓库当前 `7f29a657` 源码构建的 Linux/arm64 测试程序，未修改该仓库。

## 实现范围

- AN 管理后台新增 `/admin/node-connections`。测试节点的地址、TLS SHA-256 指纹、加密 Token 和启停状态独立保存；Token 不回显。
- 现有面板客户端支持明确指定的 3x-node 目标。自营 3x-ui 仍使用原全局配置。节点请求限于六个原有白名单接口，自签证书必须匹配固定指纹；不允许重定向或降级校验。
- 测试连接只用于管理员手动联调，不进入 `nodes`、用户订阅、worker 同步、套餐扣量或卖家账本。

## 环境与结果

本地 Docker 运行 3x-node 和 Xray 26.7.28；管理口映射到 `127.0.0.1:32053`，VLESS 测试入站映射到 `127.0.0.1:32443`。另用独立 MySQL 8.4 容器与 `aeranexa_node_lab` 数据库验证后台；未连接主工作目录的数据库。TLS 指纹由测试证书计算，Token 仅从隔离配置读取，未写入仓库。

| 验证项 | 结果 |
| --- | --- |
| `GET server/status`、`GET inbounds/list` | 实机通过；返回节点版本 `0.1.24-node`、Xray `26.7.28` 和 1 个 VLESS 入站 |
| `POST clients/add`、`update/{email}`、`{email}/detach`、`del/{email}` | 实机通过；随机 `an-test-*` 身份可创建、更新、摘除、重新挂载并删除；清理后列表无测试身份 |
| TLS 指纹不匹配 | 自动化测试证实在发送 HTTP 请求前拒绝；无跳过证书校验回退 |
| 错误 Token、超时、接口白名单 | 自动化测试通过；分别按 401、超时和本地拦截处理 |
| 独立配置 | 隔离数据库中新增记录默认停用；停用后后台测试被拒绝；重新启用后成功。数据库保存的是 AES-256-GCM 密文、IV 和认证标签，页面未回显 Token |
| 后台可见路径 | 登录后 `/admin/node-connections` 返回 200，显示测试节点与操作按钮；未登录访问重定向登录页 |

## 流量计数实测

使用独立 Xray 客户端经测试 VLESS 入站访问本地 HTTP 源站：GET 响应体 65,536 字节，POST 请求体 32,768 字节。节点在一次采样周期后上报 `up=33,026`、`down=65,765` 字节；读数大于纯请求/响应体，是包含 HTTP 报文开销的合理结果。连续两次 `inbounds/list` 读取相同计数，未因查询而重复增长。

重启节点后读数仍为 `33,026 / 65,765`。随后在**隔离节点**调用重置接口并再次 GET 65,536 字节，读数从新世代累计到 `up=92`、`down=65,650`。这说明节点侧累计计数可读取、持久化并可重置；AN 尚未把这些读数用于买家扣量或卖家结算，也未验证受恶意卖家控制时的可信性。
