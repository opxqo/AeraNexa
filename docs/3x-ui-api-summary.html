认证与安全模型 所有 /panel/api/* 接口共用

① 会话 Cookie

浏览器登录方式。POST /login 后由服务端下发 3x-ui 会话 Cookie。

  • 非安全请求需带 X-CSRF-Token 头（由 GET /csrf-token 签发）
  • Cookie 属性：HttpOnly、SameSite=Lax、HTTPS 下 Secure
  • 有效期由 sessionMaxAge 设置控制

② Bearer API Token

在「设置 → 安全 → API Token」创建，Authorization: Bearer <token>。

  • admin — 全权，等同面板密码
  • monitor — 仅只读监控白名单（status / history / 日志版本等）
  • node-sync — 仅节点同步白名单（inbounds/clients 增删改、流量推送等）
  • 明文仅创建时返回一次，库中只存哈希

③ mTLS 客户端证书

节点间通信用。TLS 握手完成且证书通过校验即视为已认证。

  • 由 nodes/mtls/ca 签发 CA，节点侧用 mtls/trustCA 信任
  • 证书认证自动获得 node-sync 范围
  • 可在 HTTPS 面板上选开启，不影响浏览器访问

其他防护

  • 请求体上限 10 MiB（importDB 除外，需流式接收大备份）
  • 节点配置信封：zstd + X-Config-Sha256 校验
  • 登录失败限流（login_limiter.go）
  • 可配置 Web 域名校验、安全响应头 / HSTS
  • 未认证 XHR 返回 401，裸请求返回 404（减少扫描面）

给 AeraNexa 的对接要点 结合本项目边界

浏览器不直连管理 API

本项目 README 已定界：浏览器不得直接调用 3x-ui 管理接口，也不持有管理凭据。上表 /panel/api/* 全部应由服务端适配层代理，凭据只存在于服务端环境变量。

最合适的对接凭据

若后端只做节点编排，用 node-sync 范围的 API Token 即可覆盖 inbounds / clients 同步与流量推送；监控面板数据用 monitor 范围，避免使用 admin 全权令牌。

订阅接口是用户侧出口

「Subscription Server」四个接口不在 /panel/api 下、无需认证（subId 即凭据），路径由 subPath / subJsonPath / subClashPath 配置决定且默认随机化。这是用户订阅链接的真实来源，与 getSubscribe 返回的私有订阅地址对应。

流量数据的两套口径

pushClientTraffics 推送的数据只用于 UI 展示与本地配额判定，不并入本地计数器（保持增量计费不被打乱）。设计流量同步时不要把两者混算。
